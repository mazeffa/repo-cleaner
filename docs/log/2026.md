## 2026-09-19 (2) — Review found 4 hook bugs, one of which had already corrupted this file

Decisions: none
Docs: docs/log/2026.md, hooks/_lib.py, hooks/stop.py, skills/repo-clean/SKILL.md

**What happened.** A review of the (2) entry's hooks (not run against a live session, only
scratch copies) found four real bugs. `_strip_last_state` deleted only a wrapped `State:`
line's first physical line, orphaning its continuation as bare prose with no `State:`
prefix — the checker can't see this because orphaned prose is valid shape, and it had
already happened to the (3) entry above when its `State:` was manually moved off. Fixed by
reusing the continuation-following logic `last_state_line` already had, factored into
`_field_span`, and used to delete the whole field in `_strip_last_state` too. Restored (3)'s
orphaned line. `add_file` recorded `docs/log/*.md` itself as a changed file, so filling in
the entry (an edit to the log) fed the next Stop call, which folded the log into its own
`Docs:` line — excluded `docs/log/` from `add_file`. `run_checker` called `python`
literally; on a box without that alias (common on Linux/Mac, where it's `python3`) the Stop
hook would crash and Claude Code would fail open silently — switched to `sys.executable`.
Stop had no retry cap: a finding Claude can't fix (e.g. a missing decisions file) blocked
every future Stop forever, and the message always said "fill in the headline and State:"
even when only a checker finding remained. Fixed: the message now names which condition
actually failed, a per-session retry counter caps it at 3, and the fourth attempt fails
open with a warning instead of wedging the session shut.
